# 评测说明

## 质量门禁

项目把质量拆成四层，避免只看一条主观回答：

1. 回归测试：代码行为、安全边界、接口契约和降级逻辑。
2. 检索评测：目标产品、知识图片召回和跨产品污染。
3. Agent 评测：意图、动作和转人工策略。
4. 生成评测：真实模型回答关键词和知识图片选择。

## 2026-09-27 已验证结果（Mock 基线口径）

| 评测 | 数据规模 | 结果 |
| --- | ---: | --- |
| Mock 回归 | 20 组测试模块 | 20/20 通过 |
| 检索评测 | 13 个跨产品案例 | 13/13 通过，100% |
| Agent 路由 | 17 个策略案例 | 17/17 通过 |
| Agent 指标 | 意图、动作、转人工 | 准确率 100%，转人工 F1 100% |
| HTTP 性能 | 50 请求，并发 5 | 0% 错误，P95 177.150 ms，31.744 req/s |

性能测试使用本地 Mock 文本模型、本地 BGE Embedding 和本地 SQLite。首次模型加载由预热阶段排除，结果反映热服务状态下的 API、检索和存储基线。

## 2026-10-02 评测集扩容与失败迭代

把三层评测集扩大并引入对抗案例后，"100% 通过"变成了有信息量的分数：

### 检索评测：13 → 56 案例

新增 43 案例覆盖全部 20 个产品，并加入口语化、错别字、产品简称对抗案例。首轮 53/56 通过，3 个失败对应三类真实缺陷：

| 失败案例 | 缺陷类型 | 处理 |
| --- | --- | --- |
| `adv_mouse_battery_shorthand`（"鼠标用几号电池"） | 产品别名缺失，硬过滤失效，电钻记录混入 | 新增 19 条产品别名词典，修复转绿 |
| `fridge_temp_adjust`（"冷藏室温度怎么调节"） | 隐式指代识别不到产品，空调记录混入 | 同上（别名"冷藏室"→冰箱），修复转绿 |
| `generator_home_wiring`（接入建筑物电气系统） | 排序缺失：目标片段被语义相近的接地片段挤出 top20 | 标记 `known_failure`（xfail），留待重排优化 |

当前 55/56 通过 + 1 已知失败。

### Agent 路由：17 → 59 案例

新增 42 案例重点测试真实表述：口语化安全描述、裸词转人工、业务同义说法、拟声词故障、知识库外问题。**旧规则真实水平：通过率 45.76%，转人工 Recall 50%**（12 个口语化安全表述全部漏判为普通问题）。逐条分析 32 个失败后按五类缺口补词，修复后 59/59 全部通过，旧 17 案例无回归。

### 生成评测：5 → 12 案例

新增 7 案例（与检索评测同源出题）。两轮真实运行暴露三类生成层问题：

1. 提示词写死"只选一张代表图片"，导致模型选图与回答引用的片段脱节 → 修改提示词为"每个实际依据的片段各选一张代表图"。
2. 模型选图稳定偏向候选排名靠前的图片（如总览片段），精确图片 ID 匹配度量的是出题人选片偏好而非回答质量 → 判分口径改为：门禁 = 关键词覆盖 + 返回图片零跨产品污染；"至少命中一张预期图片"与"精确覆盖"降为参考指标上报。
3. `vr_headset_child_age` 回答正确但未出现判分关键词组 `[安全/风险/警告]`，关键词判分对"语义正确但措辞不同"误判 → 待 LLM-as-judge 阶段解决。

当前 11/12 通过（91.67%），expected_image_hit 8/12，跨产品污染 0。

## 真实模型评测（2026-10-02）

### 模型口径

| 用途 | 供应商 | 模型 |
| --- | --- | --- |
| 文本生成 | 智谱 BigModel | `glm-4.5-flash`（免费） |
| 视觉预分析 | 阿里云百炼 | `qwen3-vl-flash` |

原配置的 `glm-4.5-air` 因账户余额不足返回错误码 `1113`（外部表现为 429）。这类失败属于账户资源问题，重试与熔断无法恢复，只能切换模型或充值；切换后全链路真实调用打通。

### 结果

| 评测 | 结果 |
| --- | --- |
| 真实模型生成评测 | 5 案例 4/5 通过（80%） |
| 真实多模态 live 回归 | 21/21 通过 |
| 真实模型 HTTP 基线 | 20 请求、并发 2、0% 错误、P50 4.48 s、P95 6.45 s、P99 10.77 s、0.41 req/s |

### 生成评测失败分析

`vr_headset_child_age`（"12岁以下的儿童可以使用这款VR头显吗？"）回答为"VR头显不适用于12岁以下儿童"，事实正确且命中预期知识图片，但未出现判分关键词组 `[安全/风险/警告]` 中任意词，被判为失败。

结论：**回答质量没有问题，是关键词判分口径过严**。该案例说明纯关键词判分对"语义正确但措辞不同"的回答会误判，已列入 LLM-as-judge 评测升级计划。

### 口径说明

- 真实模型基线中 P95 主导项是大模型生成耗时（秒级），Mock 基线 P95 177 ms 度量的是 API、检索与存储编排层本身，两者不可直接比较。
- 真实模型压测建议显式放宽阈值，例如 `--max-p95-ms 15000`；默认 5000 ms 阈值只适用于 Mock 口径。

## 检索消融实验（2026-10-02）

在 56 个检索案例上对比混合检索各设计层的贡献（`python -m scripts.ablation_retrieval`）：

| 配置 | 图片Recall@10 | 图片Recall@20 | MRR | 产品一致性 | 平均延迟ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| keyword_only | 1.54% | 1.54% | 0.018 | 100%* | 0.9 |
| keyword_only_neighbor | 6.15% | 6.15% | 0.013 | 100%* | 1.1 |
| vector_only | 93.85% | 96.92% | 0.777 | 32.73% | 8.9 |
| hybrid_no_filter | 93.85% | 96.92% | 0.785 | 32.73% | 10.2 |
| hybrid_full（当前管线） | 95.38% | 98.46% | 0.783 | 100% | 10.2 |

结论：

1. **向量检索承担几乎全部召回**：纯关键词路径只对型号类查询有效（Recall@20 仅 1.54%），因为客服问题的自然语言表述与手册原文几乎无字面重叠。*keyword 配置的产品一致性 100% 是低召回的副产物（返回结果极少），不构成优势。
2. **产品硬过滤是性价比最高的一层**：一致性 32.73% → 100%，召回@20 反而提升 1.54pp，延迟零增加——代价被"先取 3 倍语义候选再过滤"的设计吸收。
3. **关键词通道仍值得保留**：合并后 Recall@20 96.92% → 98.46%，且它对 `DCB107` 这类型号精确查询是不可替代的兜底。
4. 已知失败案例 `generator_home_wiring` 在所有配置下都无法进入 top20，确认为排序问题而非召回配置问题，重排（rerank）是下一个优化方向。
